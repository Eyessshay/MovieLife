# Stage 16.4 确定性演示数据

本目录只保存演示数据，不属于正式 Schema 或 Migration。权威表结构仍为
`sql/movielife.sql`。演示主键保留区间为 `1604000000..1604999999`，名称统一带
`[DEMO-16.4]`；演示场馆及其场次、订单和场次座位构成可安全清理的演示数据闭包。

预置场次每次安装时统一更新为 MySQL 当前日期后第 2 天 19:30～21:30，6 个
ShowtimeSeat 全部为 `AVAILABLE`，且 `total_seats = available_seats = 6`。安装程序在
发现演示场馆已有订单时拒绝覆盖，要求先安全重置，避免改写真实接口产生的交易状态。
数据集不预造订单、票码或 Redis 锁座。

## 操作入口

基础设施健康且 Demo 应用停止时，可在仓库根目录执行：

```powershell
.\demo-data-install.ps1
.\demo-data-check.ps1
.\demo-data-reset.ps1 -Force
```

`demo-up.ps1` 会在启动应用前自动执行安装和检查。安装可重复执行；检查只接受未开始
交易的基线状态。重置先根据演示场次和演示用户精确删除登录态、锁座 Token、座位锁、
详情/摘要缓存及 GEO 成员，再按外键顺序删除演示 MySQL 数据。共享 Redis GEO Key 只
`ZREM` 两个演示 Venue 成员，不删除整 Key；未知或无法证明归属演示数据的 Key 保留。

重置要求显式 `-Force`，并在 Demo 应用仍运行时拒绝执行。它不使用 `DROP DATABASE`、
`TRUNCATE`、全库扫描删除或基础设施数据卷清理。若非演示业务记录引用演示用户，外键会
让重置明确失败，而不是通过关闭外键检查破坏数据。
